## 1. Описание задания и архитектуры

Во втором задании сервис переписан с использованием современного веб-фреймворка **FastAPI** (Python-аналог Spring Boot) с реализацией **слоистой архитектуры (Layered Architecture)** и **внедрения зависимостей (Dependency Injection)**.

### Слоистая архитектура:
1. **Слой контроллеров / роутеров (`app/routers/`)**:
   - `app/routers/users.py`: обработка HTTP-запросов пользователей (`/api/users`).
   - `app/routers/scooters.py`: обработка HTTP-запросов самокатов и доменных операций (`/api/scooters`).
   - Использует `Depends(get_service)` для внедрения бизнес-сервиса (аналог `@Autowired` в Spring).
2. **Слой валидации и DTO (`app/schemas.py`)**:
   - Pydantic-схемы валидации входных данных и строгой типизации ответов (аналог `spring-boot-starter-validation`).
3. **Слой внедрения зависимостей (`app/dependencies.py`)**:
   - Предоставляет зависимости `get_repository()` и `get_service()` для слабой связанности слоев.
4. **Слой бизнес-логики (`app/service.py`)**:
   - Класс `RentalService` содержит всю предметную логику (аренда, возврат, зарядка, лимиты тарифов).
   - Получает репозиторий через конструктор (Constructor Dependency Injection). Полностью независим от веб-фреймворка.
5. **Слой доступа к данным / репозиторий (`app/repository.py`)**:
   - Класс `InMemoryRepository` инкапсулирует хранение данных в оперативной памяти.
6. **Слой доменных моделей и исключений (`app/models.py`, `app/exceptions.py`)**:
   - Модели `User`, `RegularUser`, `VipUser`, `Scooter`, статус `ScooterStatus`.

## 2. Предметная область и правила

- **Ресурсы**: Пользователи (`User`) и Самокаты (`Scooter`).
- **Различие типов пользователей**:
  - `RegularUser` (обычный): лимит **1** самокат одновременно (`max_rentals = 1`).
  - `VipUser` (VIP): лимит до **3** самокатов одновременно (`max_rentals = 3`).
- **Доменные операции**:
  1. `POST /api/scooters/{id}/rent` — аренда самоката (проверка статуса `available`, заряда $\ge 20\%$, лимита тарифа).
  2. `POST /api/scooters/{id}/return` — возврат самоката (списание заряда, автоматический перевод в `maintenance` при заряде $< 20\%$).
  3. `POST /api/scooters/{id}/charge` — зарядка батареи (запрещена во время поездки; при заряде $\ge 20\%$ статус меняется на `available`).
- **Согласованность данных**:
  - Изменение уровня заряда через `PUT /api/scooters/{id}` во время поездки запрещено (`409 Conflict`).
  - Статус `available` присваивается самокату только при заряде $\ge 20\%$, иначе `maintenance`.

## 3. Спецификация API

Автоматическая интерактивная документация Swagger UI доступна по адресу:
👉 **`http://localhost:8080/docs`**

| Метод | Путь | Описание | Коды ответов |
|---|---|---|---|
| `GET` | `/ping` | Проверка работоспособности сервиса | 200, 405 |
| `GET` | `/` | Справочная информация о сервисе | 200 |
| `GET` | `/docs` | Интерактивная документация Swagger UI | 200 |
| `GET` | `/api/users` | Список пользователей (фильтр `?type=...`) | 200 |
| `POST` | `/api/users` | Создание пользователя | 201, 400 |
| `GET` | `/api/users/{id}` | Получение пользователя по ID | 200, 404 |
| `PUT` | `/api/users/{id}` | Редактирование пользователя | 200, 400, 404, 422 |
| `DELETE` | `/api/users/{id}` | Удаление пользователя (запрещено при активной аренде) | 200, 404, 422 |
| `GET` | `/api/scooters` | Список самокатов (фильтры `?status=...`, `?min_charge=...`) | 200, 400 |
| `POST` | `/api/scooters` | Создание самоката | 201, 400 |
| `GET` | `/api/scooters/{id}` | Получение самоката по ID | 200, 404 |
| `PUT` | `/api/scooters/{id}` | Редактирование самоката | 200, 400, 404, 409 |
| `DELETE` | `/api/scooters/{id}` | Удаление самоката (запрещено во время аренды) | 200, 404, 422 |
| `POST` | `/api/scooters/{id}/rent` | Доменная операция: аренда самоката (`{"user_id": 1}`) | 200, 400, 404, 409, 422 |
| `POST` | `/api/scooters/{id}/return` | Доменная операция: возврат самоката (`{"battery_used": 20}`) | 200, 400, 404, 409 |
| `POST` | `/api/scooters/{id}/charge` | Доменная операция: подзарядка (`{"amount": 50}`) | 200, 400, 404, 409 |

## 4. Структура проекта

```text
scooter-rental-service/
├── .vscode/
│   ├── launch.json          # Конфигурация запуска F5 в VS Code
│   └── settings.json        # Настройки редактора
├── app/
│   ├── __init__.py
│   ├── dependencies.py      # Внедрение зависимостей (Dependency Injection)
│   ├── exceptions.py        # Доменные исключения (400, 404, 409, 422)
│   ├── models.py            # Доменные модели (User, RegularUser, VipUser, Scooter)
│   ├── repository.py        # Репозиторий хранения в оперативной памяти (In-Memory)
│   ├── schemas.py           # Pydantic DTO схемы запросов и ответов
│   ├── service.py           # Бизнес-логика (не зависит от HTTP/FastAPI)
│   └── routers/
│       ├── __init__.py
│       ├── scooters.py      # Контроллер самокатов и доменных операций
│       └── users.py         # Контроллер пользователей
├── tests/
│   ├── __init__.py
│   └── test_service.py      # Юнит-тесты бизнес-логики (без запуска сервера)
├── pyproject.toml           # Зависимости проекта (FastAPI, Uvicorn, Pydantic)
├── requests.sh              # 32 curl-запроса для проверки всех сценариев
├── main.py                  # Запуск FastAPI приложения
└── README.md
```

## 5. Запуск и тестирование

### 1. Запуск сервиса
```bash
python3 main.py
```
Сервис доступен по адресу `http://localhost:8080`.
Интерактивная документация: `http://localhost:8080/docs`.

### 2. Запуск curl-проверок
В отдельном окне терминала выполните:
```bash
./requests.sh
```

### 3. Запуск модульных тестов
Юнит-тесты проверяют исключительно бизнес-логику без запуска веб-сервера:
```bash
python3 -m unittest discover tests
```
