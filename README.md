## Описание проекта

В третьем задании сервис переведен на сохранение данных в реляционной базе данных PostgreSQL с использованием ORM (SQLAlchemy) и механизма миграций схемы (Alembic).

### Реализованные требования:
1. **Персистентность данных**: все сущности сохраняются в базе данных PostgreSQL. При перезапуске приложения данные не теряются.
2. **Связи между ресурсами и целостность**:
   - Связь между пользователями (`users`) и самокатами (`scooters`) через внешний ключ `current_user_id` с правилом `ON DELETE RESTRICT`.
   - Журнал аренд (`rentals`) сохраняет полную историю завершенных поездок даже при последующем удалении пользователя или самоката (`ON DELETE SET NULL`).
   - Запрещено удалять пользователя с активной арендой и занятый самокат. Ссылки на несуществующие ресурсы не допускаются.
3. **Транзакционность и блокировки**: операции аренды (`POST /api/scooters/{id}/rent`), возврата (`POST /api/scooters/{id}/return`) и обновления изменяют сущности в рамках транзакции БД с блокировкой строк (`with_for_update`) и синхронизацией потоков. При возникновении ошибки происходит полный откат.
4. **Миграции базы данных (Alembic)**:
   - `001`: создание начальных таблиц `users` и `scooters`.
   - `002`: добавление таблицы `rentals` (журнал поездок) с сохранением накопленных данных.
   - При старте приложения миграции применяются автоматически до актуальной версии (`head`).
5. **Оптимизация запросов (защита от N+1)**: получение списков ресурсов со связанными данными выполняется через жадную загрузку (`joinedload`), что исключает N+1 запросов при росте объема данных.
6. **Тестирование**: предметная логика, работа с БД, сохранение истории аренд и многопоточная конкуренция покрыты юнит-тестами без поднятия веб-сервера.

## Основные эндпоинты

- `GET /ping` — проверка работы сервиса
- `GET /` — краткая информация о сервисе
- `GET /docs` — Swagger UI документация
- `GET, POST /api/users` — список (включая арендованные самокаты) и создание пользователей
- `GET, PUT, DELETE /api/users/{id}` — получение, редактирование и удаление пользователя
- `GET, POST /api/scooters` — список (включая текущего арендатора) и создание самокатов
- `GET, PUT, DELETE /api/scooters/{id}` — получение, редактирование и удаление самоката
- `POST /api/scooters/{id}/rent` — аренда самоката (транзакция)
- `POST /api/scooters/{id}/return` — возврат самоката (транзакция)
- `POST /api/scooters/{id}/charge` — зарядка самоката
- `GET /api/rentals` — журнал всех поездок и связанных объектов

## Запуск и проверка

### 1. Настройка подключения к БД
По умолчанию сервис подключается к PostgreSQL: `postgresql+psycopg2://postgres:postgres@localhost:5432/scooter_db`.

Запустить PostgreSQL можно одной командой через Docker Compose:
```bash
docker compose up -d
```

При необходимости адрес можно переопределить через переменную окружения `DATABASE_URL`:
```bash
export DATABASE_URL="postgresql+psycopg2://postgres:postgres@localhost:5432/scooter_db"
```

### 2. Запуск сервера
При первом запуске автоматически применятся миграции Alembic и инициализируются начальные данные:
```bash
python3 main.py
```
Сервер доступен на `http://localhost:8080`.

### 3. Запуск тестов
```bash
python3 -m unittest discover tests
```

### 4. Проверка curl-запросами
В отдельном терминале:
```bash
./requests.sh
```
